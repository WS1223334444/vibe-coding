# frontend-check（前端改动检查）

## 触发时机

凡是要改动 `index.html` 的样式、结构或交互逻辑——无论加功能、修问题还是重构——**动手前后都必须各执行一遍本 Skill 的检查步骤**，并把两次调用的结论记录在 `usage-log.md`。

## 检查步骤

### 动手前

1. 核对这次改动对应 PRD 哪条验收项；若是 PRD 未列的新增功能，写明来源（课程任务 / 用户要求）并确认不触碰「本期不做」清单；
2. 列出改动范围（哪些文件、哪几行）请用户确认；
3. 声明本次改动预期影响的页面状态（四态中的哪几个）。

### 动手时

4. 一次只改一个问题，不夹带、不顺手优化与本次目标无关的代码。

### 动手后

5. **页面冒烟（必须先做，2026-09-27 事故教训）**：实际打开页面确认正常态完整渲染、无 JS 报错——**代码级推断不算数**；可用 Node `new Function` 编译页面脚本做语法兜底。新增代码的变量声明、函数签名、事件绑定都可能让没碰过的状态直接崩掉；
6. 逐项验证：
   - ① 四种页面状态（正常 / 加载 / 空 / 错误）全部不破；
   - ② 对比度：正文 ≥ 4.5:1，辅助文字颜色不浅于 #888；
   - ③ 间距：相关内容靠近、无关内容远离，条目行内边距 ≥ 15px；
   - ④ 对齐：全页共享同一条左边线，不混用对齐方式；
   - ⑤ 反馈：新增交互必须三要素齐全（即时 / 就地 / 说明结果）；
   - ⑥ 连续快速操作 3 次以上不出错、不串台。

## 通过标准

- 上述 5–6 项全部通过才算过；
- 任何一项不过，修复后重走「动手后」检查；
- 连续两次不过，停下来报告，不带病闯关。
