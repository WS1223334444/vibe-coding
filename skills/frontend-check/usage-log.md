## 调用 #2 修正记录｜2026-09-27 ｜ Day 12

- **漏检事故**：上表 ①「四态不破」我当时判定 ✅——但只做了代码级推断，**没有做页面级冒烟验证**。实际上本次实现漏写了三个变量声明（`itemsRef` / `currentLimit` / `filterBar`），脚本执行到「给筛选条挂监听」时抛 ReferenceError，**渲染代码一行都没跑**——页面卡在「加载中…」、榜单空白、日期不更新。四态里的「正常态」恰恰被改破了，而调用 #2 却给了 ✅。
- **用户发现方式**：浏览器打开 `localhost:8000` 截图（卡「加载中…」、榜单空白、筛选条在但无反应）。
- **修复**：在 `CACHE_KEY` 声明后补三行变量声明；用 Node `new Function` 编译页面脚本做语法体检通过。等用户 Ctrl+F5 复测。
- **教训（已写回 SKILL.md）**：**代码级推断 ≠ 页面级验证**。「四态不破」必须包含一次真实页面冒烟（本地打开确认正常态完整渲染、无 JS 报错；可用 Node 编译脚本做语法兜底），不能因为「没改那部分代码」就跳过——新增代码的变量、函数签名、事件绑定都可能伤到没碰过的状态。
